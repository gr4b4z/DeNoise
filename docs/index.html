Alert Management Reimagined

DeNoise is a sophisticated multi-tier alert management platform that deduplicates, auto-resolves, and intelligently routes alerts across your infrastructure

Get Started View on GitHub

Core Features

Built-in capabilities for modern alert management

🎯

Smart Deduplication

Automatically identify and deduplicate similar alerts using intelligent fingerprinting. Reduce alert fatigue by 80% with grouping based on alert content, source, and severity.

⚙️

Auto-Resolution

Automatically resolve alerts when source systems report recovery. Configurable resolution policies with timeout-based cleanup for stale alerts.

✅

Coverage Verification

Verify that all expected sources are reporting. Detect when critical integrations go silent with heartbeat monitoring and coverage dashboards.

📢

Multi-Channel Routing

Route alerts to Slack, PagerDuty, webhooks, email and more. Dynamic routing policies based on alert severity, source, and team ownership.

📊

Episode Lifecycle

Track alert episodes from creation through resolution. Automatic grouping of related alerts with timeline, state transitions, and audit trail.

🔐

Enterprise Security

Role-based access control, OIDC/OAuth2 integration, encrypted webhooks, and comprehensive audit logging for compliance.

Architecture

Multi-tier design for scalability and reliability

Core Components

Ingest Layer

Purpose: Accept alerts from diverse sources
Features: Webhook ingestion, batch processing, alert validation, deduplication fingerprinting, durable job queue
Tech: .NET 10, async message queue

API Layer

Purpose: REST API for alert management
Features: CRUD operations, real-time SSE, policy management, audit trail, configuration export/import
Tech: .NET 10 Minimal APIs, OpenAPI v3.1

Worker Layer

Purpose: Async processing and notifications
Features: Alert routing, auto-resolution, coverage verification, retention cleanup, webhook delivery
Tech: .NET 10 Hosted Services, Outbox Pattern

Data Persistence

PostgreSQL Database

Partitioning: Daily-partitioned raw_event table for time-series efficiency
Retention: Automatic partition drops and row deletion with configurable policies
Indexes: Episode lookup, fingerprint search, timestamp range queries

Real-Time Updates

Technology: Server-Sent Events (SSE)
Features: Live alert updates, episode state changes, policy modifications
Benefit: No polling, instant UI sync across connected clients

Transactional Outbox

Pattern: Outbox table for guaranteed message delivery
Usage: Webhook routing, notification delivery, audit events
Resilience: Handles failures and retries atomically

Advanced Capabilities

Mapping DSL

Domain-specific language for alert transformation and normalization. Map external alert formats to DeNoise schema.

Policy Engine

Version-controlled policies with impact preview. Shadow mode for testing policy changes without live impact.

Webhook Templates

Sandboxed rendering with Liquid templates. Secure preview of webhook payloads before sending.

REST API Overview

Complete OpenAPI v3.1 specification

Alert Endpoints

POST /api/alerts
Ingest a new alert or group of alerts
GET /api/alerts/{id}
Retrieve a specific alert by ID
GET /api/episodes
List alert episodes with filtering and pagination
PUT /api/episodes/{id}/resolve
Manually resolve an episode

Policy Endpoints

GET /api/policies
List all routing and deduplication policies
POST /api/policies
Create a new policy with version tracking
POST /api/policies/{id}/preview
Preview policy impact without deploying

Configuration Endpoints

GET /api/config/export
Export full configuration as YAML bundle
POST /api/config/import
Import configuration from YAML

Audit Endpoints

GET /api/audit
Query audit log with keyset pagination

Full Documentation: Complete OpenAPI v3.1 specification available at /docs/openapi/
Interactive API: Swagger UI available at /swagger on the running API server

Getting Started

Deploy DeNoise in your environment

Quick Start with Docker Compose

Deploy the complete stack locally with PostgreSQL and all services:

git clone https://github.com/gr4b4z/denoise.git cd denoise docker compose up -d # API: http://localhost:5000 # Web UI: http://localhost:5173 # PostgreSQL: localhost:5432

The stack includes:

  • PostgreSQL 13 with pre-configured database
  • Mailpit (development email service)
  • DeNoise API server
  • React web application

Kubernetes Deployment

Deploy to Kubernetes using Helm charts:

helm repo add denoise https://github.com/gr4b4z/denoise/deploy helm repo update helm install denoise denoise/denoise \ --namespace denoise --create-namespace \ --values values.yaml

Production-ready configuration includes:

  • Multi-replica deployments
  • Horizontal Pod Autoscaling
  • Service mesh integration
  • Persistent volume claims for data
  • Network policies and RBAC

Local Development Setup

Set up the development environment:

# Prerequisites: .NET 10 SDK, Node.js 20+, PostgreSQL 13 # Backend setup cd src dotnet restore dotnet build # Run migrations cd DeNoise.Migrator dotnet run # Frontend setup cd ../../web pnpm install pnpm dev # Run backend services (in separate terminals) cd ../src/DeNoise.Api dotnet run cd ../src/DeNoise.Ingest dotnet run cd ../src/DeNoise.Workers dotnet run
