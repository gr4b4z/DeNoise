# Changelog

All notable changes to Alert Hub are recorded here. The format follows
[Keep a Changelog](https://keepachangelog.com/en/1.1.0/); versions follow SemVer once the pilot starts.

## [Unreleased]

### Added
- **Milestone 8 (backend) — Azure Monitor + Atlas integrations, mapping API, failures, replay.** Reference mappings of 07 §2–3 seeded active on integration creation (Azure common schema, canary ⇒ heartbeat, Resource Health, Service Health; Atlas webhook with `X-MMS-Event` fallback), Atlas HMAC signature verification on ingest (sha1/sha256, base64/hex, required or verify-only), Atlas Admin API state-query adapter (`queryable_state`) and `api_probe` coverage method with the probe worker, integration `PUT` with `If-Match` (HMAC, Atlas credentials, coverage, profile defaults, IP allow list, active/shadow), mapping versions API with draft/stored preview (fields, identity, fingerprint, routing outcome) and activation, mapping failure queue with dismiss, replay jobs (`retry_failed`, `historical`) with `ops.job.result` (migration `JobResult`) and audit. Scenarios: *Explicit-recovery-style Azure flows*, canary ⇒ coverage, Atlas one condition, *Ingestion or mapping unhealthy* (failure rate), Atlas signature, replay. See `docs/milestones/M8-integrations.md`.
- **Milestone 7 (UI) — Destinations and templates screens.** `web/`: destination list, create/edit form (masked URL, headers, template picker with server-rendered live preview against the sample or a real episode, event types, fallback or first pair, signing-secret rotation shown once), send test with inline result, reveal with password, deliveries tab; template list with built-in badge, CodeMirror Liquid editor with version rail, line diff, live draft preview, inline validation, model reference and activation; built-ins clone-only. Test sends now leave a terminal outbox row and delivery attempt. Playwright `destinations.spec.ts`; CI e2e env gains the insecure-destination switch and a raised login limit.
- **Milestone 7 (backend) — Webhook templates + destination management.** `cfg.webhook_template` with versions and one active version per id, Liquid rendering through a sandboxed Fluid engine (plain-data model only, default filters, 200 ms budget, 256 KiB cap, `json` format escapes every value and must parse), built-ins `generic-json`, `teams-adaptive-card`, `slack-blocks`, `plain-text` seeded at startup, template API (`/api/v1/webhook-templates`: list, versions, create with sample verification, draft/version preview, activate), dispatcher renders the destination's template at send time with the template's content type and treats render failure as a permanent failure with `hub.delivery_failure` to the fallback; destination `PUT` with `If-Match` (URL, headers, signing-secret rotation returned once, timeout, event types, template, active), `POST /test` through the real channel, `POST /reveal` with password re-entry, `GET /deliveries`; migration `WebhookTemplates`. New package: Fluid.Core. Scenario: *Webhook destination fails permanently* via the template path. See `docs/milestones/M7-templates-and-destinations.md`.
- **Milestone 6 — Registered heartbeats.** `hb.heartbeat` / `hb.run`, interval and cron schedules (Cronos, IANA zones, DST-safe), the 04 §10 state machine, ping API on the ingest host (`GET|POST /hb/{keyId}.{token}`, `/start`, `/fail`, `/exit/{code}`, 200/404/429, output tail stored, run ring), scheduler detection of late/missed with `FOR UPDATE SKIP LOCKED`, one miss episode per outage owned by the declared team with `heartbeat.missed` / `heartbeat.recovered` and evidence `source` on recovery, pause/resume with actor and reason, maintenance auto-pause hook, token rotation, binding to integration coverage, management API with `If-Match`, schedule preview, YAML export and import with dry-run diff, `heartbeat.changed` SSE; migration `Heartbeats`. UI: heartbeat list, create/edit form with schedule preview, one-time ping URL dialog with snippets, detail with run history, pause/resume/rotate/delete (Playwright covers the register-ping-see flow). Scenarios: *Registered heartbeat misses its schedule*, *misses many intervals*, *Cron heartbeat crosses a DST transition*, *calls /fail*, *token is rotated*, *is paused*, *Maintenance window covers a heartbeat's scope*. See `docs/milestones/M6-heartbeats.md`.
- **Milestone 5 — Auto-resolve, expiry, coverage state, dead-man ping.** Versioned `lifecycle` policies with profile presets and the spec §12.3 inactivity formula, resolved per routing rule (`lifecycle_policy`) → integration defaults → mapping hint → type preset; `auto_resolve` with all eight guards of 04 §5.3 (stale timer, due recompute, coverage suspension, backlog, mapping failures, policy re-check, source-state verification port, stale-state escalation), evidence model (`heartbeat_and_inactivity` vs `inactivity_unverified`), `stale_review`, `admin_expiry` (condition preserved), `informational_expiry`; coverage config + state machine (04 §9) with one coverage episode per outage, timer suspension/resumption and `coverage.lost/restored`; `coverage_check` and `deadman_ping` scheduler workers; policy impact preview and activation rescheduling that never closes a backlog; integration health and hub health/failures endpoints; migration `LifecycleAndCoverage`. Scenarios: *Repeating source becomes quiet*, *Source quiet, coverage never configured*, *Azure resolved lost in transit*, *Operator changes an auto-resolve timeout*, *Canary rule stops firing*, *Coverage alert flaps*, *Ingestion or mapping unhealthy*, *Old alert reaches administrative expiry*, *New signal races with expiry*, *Source resumes after expiry*. See `docs/milestones/M5-lifecycle-and-coverage.md`.
- **Milestone 4b — React UI.** `web/`: Vite + React 19 + TypeScript strict, Tailwind v4 with the 08 §0 tokens (light/dark, density), generated openapi-fetch client with CSRF / `If-Match` / `Idempotency-Key` plumbing, login and forced password change, shell with rail and counts, virtualised work queue with URL state, severity chips, keyboard triage, right-side drawer, episode detail (explanation, identity, lifecycle, routing, closure, timeline), SSE client with cache patching, stale/disconnected/polling states and a `FreshnessBar`; Vitest units, Playwright + axe e2e including *UI loses its live connection*; CI `web` and `e2e` jobs. Backend: OpenAPI response/request metadata on every endpoint, typed episode list query parameters, strict JSON numbers, SSE `heartbeat` event. See `docs/milestones/M4b-react-queue-ui.md`.
- **Milestone 4 (backend) — Application API + local auth + SSE.** Users, server-side sessions, personal access tokens, login lockout (per user and per IP), forced password change with breached list, bootstrap admin; RBAC matrix with 404 for out-of-scope resources; CSRF, `If-Match` (428/409 with current state) and `Idempotency-Key` (byte-identical replay) filters; RFC 9457 problems; episode queue read model with views, filters and keyset paging; episode actions (ack, assign/takeover, note, close, restore, silence, refresh-state, bulk); users/teams/integrations/policies/destinations endpoints; SSE stream with ids, replay and resync over PostgreSQL `LISTEN/NOTIFY`; OpenAPI snapshot + contract tests; `UsersAndAuth` migration (also `ops.coverage_state`). Scenarios: *Two users take ownership*, *User lacks resource access*, *Manual close while source is firing* (API half), *UI loses its live connection* (server half). See `docs/milestones/M4-api-auth-sse.md`.
- **Milestone 3 — Ownership + routing + outbox.** Teams (one triage team), scopes, destinations with encrypted secrets and mandatory fallback, versioned policies (`cfg.policy`) for routing and escalation, routing predicate engine with fallback-to-triage and explanations, escalation timers (`ack_deadline`, `escalation_step`), transactional outbox rows on open/severity increase/closure, dispatcher with relevance check, coalescing, ADR-7 retry classification and single-hop fallback + `hub.delivery_failure`, `WebhookChannel` (signed `generic-json`) and `SmtpEmailChannel` (MailKit). Scenarios: *No ownership rule matches*, *Worker fails after state commit* (outbox part), *Delivery succeeds but response is lost*. See `docs/milestones/M3-ownership-routing-outbox.md`.
- **Milestone 2 — Normalise + identity + episode.** Mapping DSL (all rule kinds, predicates, transforms, validation with paths, YAML↔JSON), built-in generic webhook mapping, versioned mappings with sample verification and activation; delivery key, fingerprint canonicalisation, ordering rules, `Episode` aggregate; transactional `EventProcessor` with idempotency ledger, `FOR UPDATE` episode lock, conflict retry, timeline, audit, mapping-failure quarantine; `Episodes` migration. Scenarios: *Duplicate webhook delivery*, *Two workers process one condition*, *Recovery arrives before opening*, *Old recovery during a new episode*, *Historical replay executes*, *Manual close while source is firing* (processing half). See `docs/milestones/M2-normalise-identity-episode.md`.
- **Milestone 1 — Durable ingest + queue.** `POST /ingest/{keyId}` with per-integration bearer tokens (Argon2id, key-id lookup), size and per-key rate limits, atomic raw event + `normalise` job insert and the 202/401/413/429/503 contract; `cfg.integration` versions with token rotation; `audit.entry`; PostgreSQL job queue (`FOR UPDATE SKIP LOCKED`, reservation tokens, backoff, failure queue), `JobRunner` per role, reaper, queue gauges; `seed-dev` command. Scenarios *Worker fails during processing* and *Worker fails after state commit* (job part). See `docs/milestones/M1-ingest-and-queue.md`.
- **Milestone 0 — Skeleton.** .NET 10 solution (`Domain`, `Application`, `Infrastructure`, `Contracts`, `Api`, `Ingest`, `Workers`, `Migrator` + four test projects); first migration with partitioned `alert.raw_event`, `ops.job`, `ops.outbox`, `ops.hub_component_heartbeat` and schemas `alert/ops/audit/hb/cfg`; daily partition manager; `/healthz/*` on every host; Serilog + OpenTelemetry wiring with ADR-9 metric names; `TimeProvider` injection; Docker Compose, multi-host Dockerfile, Helm chart, GitHub Actions CI. See `docs/milestones/M0-skeleton.md`.
- Handoff pack imported into `docs/` (spec v0.4, architecture and ADRs, domain model, data schema, API contract, mapping DSL, frontend spec, implementation plan, test strategy).
- `AGENTS.md` operating brief at the repository root.
